## 1. API ARCHITECTURE & CONVENTIONS

- **Base URL**: `https://api.aiworkforce.io/v1` (Production) / `http://localhost:8000/v1` (Local)
- **Format**: All request and response bodies use `application/json` encoded in UTF-8 unless otherwise specified.
- **Timestamp Format**: All datetime values use ISO-8601 UTC with explicit millisecond precision: `YYYY-MM-DDTHH:mm:ss.sssZ`.
- **Naming Convention**: JSON properties use `snake_case`. URL segments use kebab-case (`/knowledge-collections`).
- **Resource Identifiers**: All entity identifiers are RFC 4122 UUIDv4/v7 strings.

## 2. GLOBAL HEADERS, AUTHENTICATION & TENANT SCOPING

### Request Headers
| Header | Required | Description |
|---|---|---|
| `Authorization` | Yes (Protected) | Bearer JWT token: `Bearer <access_token>` |
| `X-Organization-ID` | Yes (Protected) | Active tenant UUID context: `X-Organization-ID: 018f3a9e-4b21-7299...` |
| `Idempotency-Key` | Optional | Unique UUID for deduplicating mutating requests (e.g. run triggers). |
| `X-Request-ID` | Optional | Correlation identifier passed down for OpenTelemetry tracing. |

### Response Headers
| Header | Description |
|---|---|
| `X-Request-ID` | Trace correlation identifier matching the request or generated by the gateway. |
| `X-RateLimit-Limit` | Maximum permitted requests within the rolling window. |
| `X-RateLimit-Remaining` | Remaining request quota in the current window. |
| `X-RateLimit-Reset` | Epoch timestamp (seconds) when the current window resets. |

## 3. GLOBAL ERROR SCHEMA & HTTP STATUS CODES

All error responses strictly adhere to the RFC 7807 Problem Details standard:

```json
{
  "type": "https://api.aiworkforce.io/errors/resource-not-found",
  "title": "Resource Not Found",
  "status": 404,
  "detail": "Workflow with ID 018f3b12-9921-7440-9122-849201928312 was not found in organization.",
  "instance": "/v1/workflows/018f3b12-9921-7440-9122-849201928312",
  "code": "WORKFLOW_NOT_FOUND",
  "invalid_params": []
}
```

### Common HTTP Status Codes
- `200 OK`: Request succeeded.
- `201 Created`: Resource successfully created.
- `202 Accepted`: Asynchronous task queued (e.g., workflow run started).
- `204 No Content`: Resource deleted or state cleared.
- `400 Bad Request`: Schema validation failure or malformed payload.
- `401 Unauthorized`: Missing, invalid, or expired authentication token.
- `403 Forbidden`: Authenticated user lacks the required RBAC permission.
- `404 Not Found`: Resource does not exist or belongs to another tenant.
- `409 Conflict`: Unique constraint violation or state transition conflict.
- `422 Unprocessable Entity`: Semantic validation failure (e.g., cyclic workflow graph).
- `429 Too Many Requests`: Rate limit or plan quota exhausted.
- `500 Internal Server Error`: Unhandled server exception.

## 4. PAGINATION, FILTERING & SORTING CONVENTIONS

### Query Parameters
- `limit`: Number of items per page (Default: `20`, Max: `100`).
- `cursor`: Base64-encoded pagination cursor for keyset pagination.
- `sort`: Field to sort by, prefixed with `-` for descending (e.g., `sort=-created_at`).
- `filter[field]`: Filter conditions (e.g., `filter[status]=RUNNING`).

### Standard Paginated Envelope
```json
{
  "data": [],
  "pagination": {
    "limit": 20,
    "has_more": true,
    "next_cursor": "eyJjcmVhdGVkX2F0IjoiMjAyNi0xMC0wN1QxODo...",
    "total_count": 142
  }
}
```

## 5. IDEMPOTENCY & RATE LIMITING CONTROLS

- **Idempotency Guarantee**: Submitting a mutating POST request with an `Idempotency-Key` caches the resulting response in Redis for 24 hours. Repeating the identical request returns the cached response with the `X-Cache-Lookup: HIT` header.
- **Rate Limits by Tier**:
  - `Starter`: 120 req/min per organization.
  - `Professional`: 600 req/min per organization.
  - `Enterprise`: 2,400 req/min per organization.

## 7. REAL-TIME STREAMING ENDPOINTS (SSE)

### `GET /runs/{run_id}/stream`
- **Protocol**: Server-Sent Events (`text/event-stream`)
- **Auth**: Bearer token via query parameter (`?token=...`) or header.
- **Event Stream Format**:
  ```
  event: step_started
  data: {"step_id": "node_1", "step_type": "AGENT", "timestamp": "2026-10-07T18:30:00Z"}

  event: agent_thought
  data: {"step_id": "node_1", "thought": "Searching knowledge base for policy...", "timestamp": "2026-10-07T18:30:02Z"}

  event: approval_required
  data: {"approval_id": "app_8812", "risk_level": "HIGH", "action": "refund_customer"}

  event: run_completed
  data: {"status": "COMPLETED", "output": {"result": "Success"}, "duration_ms": 4210}
  ```

## 8. WEBHOOK INGRESS & EGRESS CONTRACTS

### Ingress Webhook Trigger: `POST /webhooks/workflows/{workflow_id}/trigger`
- **Headers**: `X-AIWF-Signature: sha256=4f8b92...`
- **Payload**: User-defined JSON payload mapped into workflow variables.
- **Validation**: HMAC-SHA256 signature verification against stored webhook secret.

### Egress Notifications: `POST {client_endpoint}`
- **Headers**:
  - `X-AIWF-Event: workflow.run.completed`
  - `X-AIWF-Signature: sha256=99281a...`
  - `Content-Type: application/json`
- **Payload**:
  ```json
  {
    "event": "workflow.run.completed",
    "organization_id": "018f3a9e-2200-7299-8832-7492cbb3e200",
    "run_id": "018f3b70-6600-7900-9912-550291029315",

  ```
